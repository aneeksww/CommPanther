# Обзор архитектуры CommPanther

## 1. Высокоуровневая схема
Система состоит из двух независимых процессов, взаимодействующих через локальный TCP-канал (IPC):
1. **Процесс UI**: Интерфейс на CustomTkinter. Отвечает за взаимодействие с пользователем и настройки.
2. **Процесс сервиса**: Фоновый демон. Занимается получением писем Gmail, анализом через ИИ и вызовами внешних API.

## 2. Межпроцессное взаимодействие (IPC)
- **Транспорт**: Локальный TCP-сокет (`127.0.0.1`).
- **Протокол**: JSON-строки, разделенные переводом строки.
- **Обнаружение**: Сервис создает файл блокировки `service.lock` в `%LOCALAPPDATA%\CommPanther\runtime\`, содержащий номер порта и токен авторизации.
- **Безопасность**: Каждый запрос должен включать токен из файла блокировки.

## 3. Управление жизненным циклом
- **Единственный экземпляр**: При запуске сервис проверяет наличие действующего файла блокировки. Если он найден и сервис отвечает — процесс завершается. Если файл устарел, он очищается, и запускается новый экземпляр.
- **Автономный запуск**: UI запускает сервис через `subprocess.Popen` с флагами отключения от родителя, чтобы закрытие окна не останавливало фоновую работу.

## 4. Стратегия обработки ошибок
Все ошибки оборачиваются в класс `AppError` со стандартизированными кодами.
- Сообщения для пользователя локализованы (на русском языке).
- Технические детали пишутся в структурированные JSON-логи.
- Секреты и токены никогда не логируются.
